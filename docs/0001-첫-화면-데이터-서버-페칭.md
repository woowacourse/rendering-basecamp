# 0001. 첫 화면 데이터를 서버에서 페칭하기

- 날짜: 2026-10-17
- 상태: 채택

## 맥락

react-hybrid의 홈 화면은 `usePopularMovies`가 `useEffect`로 인기 영화 목록을 받고 있었다. 그래서 서버는 목록 없이 HTML을 보냈고, 목록은 클라이언트 JS가 실행된 뒤에야 그려졌다. 이 페칭을 서버로 옮긴다.

서버 템플릿에는 이미 `window.__INITIAL_DATA__`를 넣는 자리가 있었다(값은 빈 배열). Next.js Pages Router가 같은 문제를 어떻게 푸는지 살펴보고 그 흐름을 따르기로 했다. 처음에는 `App → MovieHomePage`로 props를 내려주도록 구현했지만, 굳이 props를 거쳐 넘길 필요가 없다고 보고 Context로 바꿨다.

## 고려한 선택지

**데이터를 HTML에 넣는 형식**
- `window.__INITIAL_DATA__ = {...}` 스크립트: 템플릿과 `global.d.ts`에 이미 있다.
- Next처럼 `type="application/json"` 스크립트를 `JSON.parse`로 읽기: 실행되지 않는 데이터로 넣을 수 있지만 템플릿과 타입을 바꿔야 한다.

**컴포넌트가 데이터를 받는 방식**
- `App` → `MovieHomePage` props: Next의 `pageProps`와 같은 모양이다. 대신 페이지까지 props를 거쳐 넘겨야 한다.
- Context + 훅: 렌더하는 바깥쪽(서버 라우트, `main.tsx`)에서 Provider로 한 번 감싸면 `App`과 페이지에 props가 필요 없다. 파일이 하나 는다.
- React Query(`dehydrate` / `HydrationBoundary`): 실무에서 흔히 쓰지만 의존성과 설정이 는다.
- 전역 변수(서버 `globalThis`, 클라이언트 `window`)를 훅이 직접 읽기: 코드는 가장 짧다. 하지만 서버의 전역 값을 모든 요청이 같이 써서, 비동기·스트리밍 렌더로 바꾸면 요청 간에 데이터가 섞일 수 있다.

**서버에서 TMDB 호출이 실패했을 때**
- 빈 목록으로 렌더
- 500 응답(Next `getServerSideProps`의 기본 동작)

## 결정

첫 화면의 인기 영화 목록은 서버 라우트에서 받아 렌더하고, 같은 데이터를 `window.__INITIAL_DATA__`로 넘겨 클라이언트가 hydrate한다. 컴포넌트는 `InitialDataContext`의 `useInitialData()`로 읽는다. 호출이 실패하면 빈 목록으로 렌더하고, 영화 상세 조회(클릭)는 클라이언트에 둔다.

## 근거

- 클라이언트가 데이터 없이 hydrate하면 첫 렌더가 서버 HTML과 달라지고(hydration mismatch) 같은 목록을 다시 받아야 한다. 그래서 서버가 렌더에 쓴 데이터를 HTML에 함께 실어 보낸다.
- 흐름은 Next Pages Router(`getServerSideProps` → `__NEXT_DATA__` → `pageProps`로 hydrate)와 같다. 차이는 데이터를 페이지 props가 아니라 Context로 넘긴다는 점이다.
- props를 굳이 거쳐 넘길 필요가 없어서 Context를 골랐다. 서버의 `renderToString`에는 `window`가 없으므로 Provider는 `App` 바깥에서 서버와 클라이언트가 각각 감싼다.
- 형식은 `window.__INITIAL_DATA__`를 유지했다. 이미 있는 자리를 그대로 써서 바꿀 코드가 가장 적다.
- 실패 시 빈 목록으로 렌더하면 `MovieHomePage`에 있던 "영화 정보를 불러오는데 실패했습니다." 문구가 그대로 보인다. 에러는 서버 로그에 남긴다.
- 상세 조회는 사용자가 클릭해야 시작되는 요청이라 클라이언트에 둔다.
- 직렬화한 JSON의 `<`를 `<`로 바꾼다. 데이터에 `</script>`가 섞이면 스크립트 태그가 거기서 끊기고 뒤 내용이 HTML로 해석되기(XSS) 때문이다.
