# 0002. 상세 페이지를 서버에서 렌더링하기

- 날짜: 2026-10-17
- 상태: 채택

## 맥락

[0001](0001-첫-화면-데이터-서버-페칭.md)에서 홈 화면의 인기 영화 목록을 서버에서 받아 렌더하도록 바꿨다. 상세 페이지(`/detail/:movieId`)도 같은 방식으로 옮긴다.

기존 `MovieDetailPage`에는 두 가지 걸림돌이 있었다.

- `react-router-dom`의 `useParams`로 영화 id를 읽는데, `package.json`에 react-router가 없어 `App`에서 주석 처리돼 있었다.
- 모달을 `useEffect` 안에서 상세 정보를 받은 뒤 `overlay.open`으로 연다. 서버의 `renderToString`은 effect를 실행하지 않으므로 서버 HTML에는 모달이 들어가지 않는다.

## 고려한 선택지

**`App`이 홈/상세 중 무엇을 그릴지 정하는 방식**
- 초기 데이터로 분기: 경로 매칭은 Express 라우트가 하고, 초기 데이터에 `movieDetail`이 있으면 상세 페이지를 그린다. 의존성이 늘지 않는다.
- react-router-dom 추가: 서버는 `StaticRouter`, 클라이언트는 `BrowserRouter`. CSR 버전과 모양이 같고 `useParams`를 그대로 쓰지만 의존성이 는다.
- 요청 경로를 `App`에 넘겨 직접 매칭: 서버는 `req.path`, 클라이언트는 `location.pathname`을 넘기고 `App`이 문자열로 비교한다.

**상세 모달을 서버 HTML에 넣을지**
- 서버 HTML에 포함: `MovieDetailPage`가 `MovieDetailModal`을 직접 렌더한다. 첫 HTML에 모달이 열린 채로 오고 클라이언트는 hydrate만 한다.
- hydrate 후 overlay로 열기: 서버는 상세 데이터만 실어 보내고 모달은 지금처럼 `useEffect`에서 연다. API를 다시 부르진 않지만 첫 HTML에는 모달이 없다.

**서버에서 렌더한 모달을 닫을 때**
- 상태로 숨기고 `history.pushState`로 주소를 `/`로 바꾸기
- 상태로 숨기기만(주소는 `/detail/:movieId` 유지)
- `location.href = '/'`로 홈을 다시 요청

## 결정

`/detail/:movieId` 라우트가 인기 영화 목록과 상세 정보를 함께 받아 `{ movies, movieDetail }`을 초기 데이터로 넘긴다. `App`은 `movieDetail` 유무로 페이지를 고르고, `MovieDetailPage`는 홈 화면 위에 `MovieDetailModal`을 직접 렌더한다. 닫으면 모달을 숨기고 주소를 `/`로 바꾼다.

## 근거

- 초기 데이터로 분기하면 의존성을 추가하지 않고, 0001에서 만든 `InitialDataContext`를 그대로 쓸 수 있다.
- 모달을 직접 렌더해야 서버 HTML에 상세 내용이 들어간다. hydrate 후 overlay로 열면 상세 데이터는 서버에서 받아도 첫 화면은 홈과 다르지 않다.
- 닫을 때 주소를 `/`로 바꿔 화면(모달 없음)과 주소를 맞추고, 새로고침 없이 처리한다.
- 상세 조회가 실패하면(없는 id, 숫자가 아닌 id 포함) 0001과 같이 서버 로그에 남기고 `movieDetail` 없이 렌더한다. 그러면 모달 없는 홈 화면이 보인다.
